- **三个实操坑（重要，已回写计划正文，非常容易踩）**：
  1. **`iptables -X` 默认只作用于 filter 表** —— `iptables -F && iptables -t nat -F && ... && iptables -X` 会残留 6 条 nat 表 `cali-*` 链。必须 `for t in filter nat mangle raw; do iptables -t $t -F; iptables -t $t -X; done`（ip6tables 同理）。
  2. **`tunl0` 删了会立刻重建**（ipip fallback 设备），因为路由表还有 5 条 Calico 路由引用它。正确顺序：**先 `ip route flush proto 80`（Calico 路由 proto 是 80）→ 再 `ip addr del <block>/32 dev tunl0` → 最后删设备**。判定干净的标准不是"设备不存在"，而是"无 IPv4 地址 + 无 10.244 路由"。
  3. **`kubectl delete node` 后 blockaffinity 和 ipamblock 都不会自动回收** —— blockaffinity 要手工删；删完等 40s ipamblock 仍在（GC 未触发），确认 64 个 allocations 全 null 后手工 `kubectl delete ipamblock 10-244-55-192-26`。
